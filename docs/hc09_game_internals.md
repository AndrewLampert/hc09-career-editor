# How the game's data and rules fit together

Notes from reading the game's own database tables, the names the game registers for them, and the (disc, version 1.00) executable. It is findings in words and numbers only: no code, no decompiled text and no game files. Each statement is marked **(data)** when it was read straight from the shipped database or a save, **(inferred)** when it is a reading of names and structure, and **(unverified)** when it is a guess. Nothing here was tested by editing the game unless it says so. Companion documents: [hc09_gamedata_findings.md](hc09_gamedata_findings.md) (the shipped tables one by one), [hc09_position_presets.md](hc09_position_presets.md) (Player Type Fit), [hc09_play_data.md](hc09_play_data.md) and [hc09_play_creator.md](hc09_play_creator.md) (plays) and [hc09_field_reference.md](hc09_field_reference.md) (fields of a save).

## 0. Caveats
- The executable I read is the disc version 1.00. The installed update is 1.02 (632 bytes larger), which a running game normally uses. Data findings do not depend on the executable; statements about how code uses the data could differ in 1.02.
- Edits to the shipped database files are **not shown to change the game**: in October a patch of the Evaluate Roster weights (both copies of the database) had no visible effect. Treat every "this table drives X" below as a statement about what the game's data and code are shaped like, not as a recipe.

## 1. The game names its own tables and fields (data)
The executable carries two lists: **1,277 table names** (653 of the 663 tables of the big shipped database `streameddata`, among them 231 enumeration tables whose names start with `E_`) and **5,648 field names** (100% of the 1,925 field ids in the shipped database, 2,151 of the 2,210 in a franchise save, all 234 columns of the player table). A table or field id like `PAWR` is therefore `PLYR_AWARENESS`, `LINC` is `LOOKUP_INJURY_CHANCE`, `PPBM` is `PROGRESSION_MULTIPLIER`. Most franchise rules are "LOOKUP_" tables of buckets: a rating or a count is first cut into bins (the bins live in the `E_..._Bin` tables, e.g. approval 0-10, 11-20, ... 91-100) and the bins index a result table.
There are two shipped databases: `streameddata` (716 tables, 13.4 MB, holds the lookup tables) and `STATICDATA` (32 tables, 87 KB, 25 tables only there: body-part weights PHCC, injury-type tables, team-event morale tables, wrong-route table WORO, bust/gem table BAGM, ...). A franchise save holds 208 tables and **none** of the lookup tables.
Floating-point fields are stored as raw bits (e.g. the draft position mix DRPB).

## 2. A player's overall (Evaluate Roster / Player Type Fit)
The overall under a team philosophy is the weighted average of grades (data for the formulas marked exact):
- **Athletic** = floor of the weighted average of 14 ratings with the philosophy's PEAW weights (exact on 350 stored prospect grades).
- **Intangibles** = floor of the weighted average of 33 ratings (PEIW weights) (exact).
- **Learning** = the Learning rating (exact).
- **Size** = floor((HTSW x height grade + WTSW x weight grade) / (HTSW + WTSW)); the height grade is looked up in table LPHG by position group and height bucket (inches: 60-65, 66-67, 68-69, 70-71, 72-73, 74-75, 76-77, 78-79, 80+), the weight grade in LPWG by position group and weight bucket (pounds: 160-183, 184-188, ... 311-319, 320+; stored weight is pounds minus 160), HTSW / WTSW come from the philosophy's PESW row (exact on 350 of 350 prospects).
- **Durability** = floor of the six body-part maximum healths weighted by the position and hand weights of PHCC/LPHC, divided by 1000 (exact for 310 of 350; defensive tackles with a high score come out one lower in the game, kickers and punters 2-3 higher; the extra component is unknown).
- **Potential** = the same combination over the grades built from the maximum ratings (exact).
- **Production** = a weighted average over stats chosen per philosophy (PEPW: stat id, weight, cap) scored against league percentiles (PGST) through grade bands (LPGS); the Evaluate Roster readings fit Production counting as 0 (inferred).
- **Overall** = floor(sum(PEOW weight x grade) / sum(PEOW weights)) over the seven grades.
With the exact Size, the 55 Evaluate Roster readings taken from the Bears (CB, SS, DT, FS) match exactly in 30 cases and within 1 point in 53 (the older approximation: 24 and 51); what is left is the durability extra part.
Out of position: table **DCSB** (75 rows) lists, for a player's own position and the position he is placed at, three ratings and the percent of each that is kept (examples: LT at RT keeps 97% awareness, 100% run block, 95% pass block; CB at FS keeps 85% awareness, man and zone coverage; QB at WR keeps 50% awareness and throw accuracy; K at P keeps 85% kick power, 60% accuracy, 75% awareness) (data). That the game applies it when it works out an off-position overall is my reading (inferred).
The game's rating ids (0 STR, 1 AGI, 2 SPD, 3 ACC, 4 AWR, 5 CTH, 6 CAR, 7 THP, 8 THA, 9 KPR, 10 KAC, 11 TAK, 12 PBK, 13 RBK, 14 JMP, 15 KRT, 16 LTR, 17 ELU, 18 BCV, 19 LSA, 20 LSM, 21 LJM, 22 LIB, 23 RBS, 24 RBF, 25 PBS, 26 PBF, 27 LPm, 28 FMS, 29 BSG, 30 LPU, 31 LPR, 32 LMC, 33 LZC, 34 IMP, 35 INJ, 36 STA, 37 TGH, 38 RSE, 39 LSC, 40 LCI, 41 LRR, 42 LHT, 43 LPE, 44 LRL, 45 MOR, 46 LRN) are used by the penalty, bust/gem, health-effect and progression tables.

## 3. Progression (data for the table shapes, inferred for the use)
LOOKUP_PROGRESSION tables: attribute levels (LPAL), attribute loss/decline (LPAl, 136 rows, 45 values per row), a coach boost modifier (LPBM: coach skill x staff points -> multiplier), one event table per position group (LPES defensive backs, LPEC offensive line, LPED defensive line, LPEH backs, LPEK kicker, LPEL linebackers, LPEP punter, LPEQ quarterback, LPET receivers/tight ends), and LPRR: ratings that grow when a player runs a given play type, by play knowledge (rating id, points; Learning and Awareness appear most). An event row says: for a player in a given years-pro bucket (0-5), this local event adds these rating points. There are 64 global progression events, each position group uses a subset (QB 12, backs 20, receivers 22, DL 19, LB 23, DB 29, OL 3, K 13, P 2). What triggers an event is not known. Player fields PPGA (progress games) and PPSP (progress stat points) are the counters on the player row.

## 4. Injuries, health and fatigue (data)
- Whether an injury happens: LINC maps position, body part, injury rating bucket (90+, 76-89, 75 or less), body-part health bucket (925+, 825-924, below 825 of 1000), fatigue bucket and severity bucket to a chance level 0-4. Injury rating 90+ gives level 0 in all but 12 of 3,402 cases (all receivers: a hit of severity 7000+ on body part 0 or 1 whose health is below 925); 76-89 averages 0.81; 75 or less 1.81; a hurt body part and a hard hit raise the level; **fatigue changes the level in only 1 of 3,402 cases**; the body part itself hardly matters. The level is 0 to 4, not a percentage: the table does not say what chance a level stands for.
- Which injury: six STATICDATA tables (head, arms, legs, torso) map chance and impact severity to an injury type. How long: LETV / LILE.
- What an injured body part does to ratings (PHAE): legs lower speed, acceleration, agility (everyone) and jumping, arms lower strength, catching, tackling and blocking, head lowers awareness (everyone), play recognition, pursuit and coverage, torso lowers agility, speed, jumping and strength.
- Morale hardly changes ratings: PMRA multipliers run from 101% to 98%.

## 5. Contracts, free agency, draft, trades
- **Contract talks** (LPCN for the user, LTCN for the CPU): chance to accept / walk away / issue an ultimatum from the number of counter offers (0-2, 3-5, 6+), the gap between the offer and the wanted package (0-6, 7-18, 19-36 steps), the player's overall bin and head coach approval (0-40, 41-70, 71-99). Small gap: about 42% accept on the first offer, 65% after six or more counters; big gap: 9-13% accept and up to 27% walk away. Higher head coach approval: 23.5% -> 38% accept. Top players are slightly harder (32.7% -> 28.5%).
- **Franchise tag** only for overall 87+ (heavy taggers: 42%, 53%, 65%, 80% by overall bin); **RFA tenders**: from level 2-3 around overall 82-86 to level 4 for 97+; **re-sign decision** chance rises with player value (37.5% -> 78.8%) and GM negotiation skill (39% -> 79%); expected in-season free agent salary starts at overall 75.
- **Draft pick values** are the classic NFL trade chart multiplied by ten (pick 1 = 30,000, pick 32 = 5,900, pick 64 = 2,700, pick 224 = 20); next year's picks are a flat fraction (round 1 = 10,000, round 2 = 4,200, round 3 = 1,900, round 4 = 700). The generated draft class position mix (percent): QB 5.5, HB 6.0, FB 4.2, WR 8.3, TE 4.2, OL 4.0 each, DE 4.0 each, DT 6.0, OLB 4.0, MLB 4.9, CB 8.3, FS 4.5, SS 4.5, K 3.7, P 3.7. The user's draft grade pays 50 points for taking the best player on the board in round 1, 35, 25, 20, 15, 10 for the next, 5 below that.
- **Bust / gem**: a hidden label shifts one key rating by 10 points (QB throw accuracy, OL pass and run block, DL power and finesse moves, LB tackling, DB awareness), 15 (HB, FB carrying) or 20 (WR, TE catching), shown after 16 games.
- **Trades**: small tables of player cost by season stage and trading philosophy, tradable value ranges by position group (flat 250 for the last two groups), and response tables with chance-based replies; how they combine is not decoded.
- **Play knowledge** rises by 0-3 points per game (learning bin x coordinator ability), decays 0.1-0.2 per game for plays in the playbook and 0.5-0.6 for others, and loses about 2 points after the season.

## 6. Owner, approval and job security (data for the shapes)
Approval is binned in 10% steps. A bonus-point table maps the bin to coach status points (looks like signed values wrapped modulo 1000: -76, -51, -26, -1, 0, +150, +250, +300, +350, +400). LOAP holds an owner reaction percentage by owner expectation level and approval bin. LJRD gives the job decision from head coach approval, salary, owner satisfaction and a job-retention level; LUOE turns owner type, expectation and win percentage into an expectation level; SOAI turns season outcomes into approval changes. What each decision code means is not decoded.

## 7. Play calling (data, inferred use)
The base weight of each candidate play comes from the playbook's AI weighting and from per-team statistics tables (PO and PD tables, one per NFL team: yards and times run by down-and-distance situation). The team's **scheme** multiplies those weights by percentages per play type: offensive schemes (WC Normal, WC Heavy Pass, Vertical Passing, Spread, Power Running) have 13 multipliers (3-step pass, inside run, 5-step pass, outside run, shotgun pass, pitch, play action, counter, screen, draw, hail mary, FB run, QB run); example WC Normal: 200, 150, 40, 120, 40, 60, 150, 100, 80, 40, 20, 20, 20 percent. Defensive rows are keyed by scheme (3-4, 4-3, 46/multiple), blitz philosophy (heavy, normal, light) and coverage philosophy (man, cover 2, zone) with 10 multipliers (man cover, cover 2, man/zone, cover 3, combo, cover 4, man blitz, zone blitz, combo blitz, kick cover). When this applies in a game (Play Now vs practice vs franchise) is unknown.

## 8. Plays, routes and the play databases
- The master playbook database (`PLAYBOOK`, 18 tables) holds the offensive step lists in `PSLO`, defensive in `PSLD`, route art in `ARTO`/`ARTD` (diagram lines); the in-game route and Play Creator databases carry step tables called `PSAL` and are **exact mirrors** of the master lists with the same ids (704 of 1,138 offensive and 247 of 403 defensive lists are covered by the union of the copies). Step-list ids are unique only within a side.
- A step is (code, val1, val2, val3). The code is the id of an assignment type (98 named: Run Route 8, Receiver Cut 9, Get Open 10, Pass Block 14, Run Block 15, Man Coverage 19, Zone Flat/Hook/CF/Deep 20-23, Show Blitz 24, Delay 25, Initial Move 26, Option Route 36, Handoff Turn 38 / Give 39 / Fake 40, Pass Rush 41, Option Run 42 ...; 255 ends a list). Run Route (read from the code, and the length and heading confirmed in the game by a tester on the Xbox 360 build): length in yards = (val1 >> 3) + (val1 & 7) / 7, heading = val2 x 2.8125 degrees (0 = right, 32 = straight upfield), third number = val3 / 255, passed to the movement component as an effort of at most 1.0 (its effect on running speed is not confirmed yet). The leg is run by the 'move in a direction for a distance' assignment: the end point is the start point plus the length along the heading, kept 3 units inside the field. Receiver Cut (code): val1 = side (1 right, 2 left), val2 picks the angle of the cut ANIMATION (1 and 23: 45 degrees, 2, 8, 9, 14, 24: 90, 3: 22, 4: 67, 22: 135, 10, 20, 21, 25: 5, every other value including 5: about 180); the cut does not set the path, the next leg's heading does, so a mismatch gives a glitchy 'two cuts in a row' (seen in the game).
- Codes 12 (QB start of option plays), 37 (option-route branch), 44 (kick-return set-up) and 45 + 46 (a pre-snap motion path with an end marker) have no name in the game and are described by where they occur (inferred).
- A receiver can run a different route than called: table WORO lists up to three alternative routes with cumulative percentages per route type; whether it is active in normal games is unconfirmed.
- Per-playbook play names (PPPN, 88 playbooks, about half (53%) differ from the master names) are what the in-game play-call screen shows.
